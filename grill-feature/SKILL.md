# grill-feature

1. Treat the user's remaining words as `TOPIC`.
2. Use the Write tool to save `TOPIC` verbatim in a new temporary topic file. Do not interpolate it through a shell command.
3. Run this Bash command with `run_in_background: true` and `timeout: 7500000ms` (the script wait cap is 7200000ms):
   `bash ~/.claude/skills/implement-spec-split/scripts/design-session.sh feature --topic-file <topic-file> --timeout 7200`
   If the command's stderr prints `提醒：本仓库还有 … Design session 没交接：`, relay that reminder verbatim to the user and ask whether to resume the old topic first (with the printed `design-session.sh --attach <运行目录>` command) or continue opening this new one; when the user has already explicitly asked for a new session, relay the reminder and continue without asking.
4. Orca switches to the new Design session tab on launch; tell the user to continue there. Do not answer design questions or poll the run directory. The script's stderr line `design-session: 本次讨论路由：讨论（design）：<档案> / <模型> / <思考强度>` names the route the session runs on (the user's `/grill-router` setting): when it is not `claude / opus`, relay that line and say the Design session runs on that model instead of Opus: say so, once. Once the handoff arrives the script switches back to this terminal and closes the Design session tab (`ISS_DESIGN_KEEP_SESSION=1` keeps it open).
5. After the completion notification arrives, read only the `handoff.md` path printed to stdout: the Spec is published and this session hands over to find-next. From the repository root run `~/.claude/skills/implement-spec-split/scripts/lock.sh status find-next-supervise --scope repo`: `held` means another session is already supervising this repository — say so and stop. `free` or `stale`: invoke the `find-next` skill in its 推进模式 (its default: no arguments, no `--suggest`, `--list` or `--watch`). find-next scans, drafts, publishes and starts the first wave itself, then supervises from this session. Do not work through the handoff's Orchestrator todo items yourself and do not run launch-wave yourself.
   - Never call implement-spec-split with the Skill tool (it sets `disable-model-invocation` and fails), create the worktree, write the Brief, or call `codex-worker.sh` yourself, whatever the handoff says about workers: find-next, launch-wave and implement-spec-split do the claim, phase marks, dispatch on the Stage route table, review, and landing.
6. On exit code 5, tell the user the Design session is still waiting, then run the `design-session.sh --attach <run-dir> ...` command printed in stderr with the same background Bash parameters. Repeat after every exit code 5, with no limit. On any other non-zero exit, report the script's stderr and stop.
7. When the user says the Design session stopped because Opus ran out of quota, do not carry on that discussion here. The design route (the user's `/grill-router` command, backed by `~/.claude/skills/implement-spec-split/scripts/stage-route.sh`, e.g. `/grill-router use design=claude-glm/glm-5.4/high`, optionally with `--for 5h`) offers two ways on; relay both and let the user choose: (a) the user switches the design route with `/grill-router`, then you run step 3 again to open a new Design session, which then runs on that route (a session that is already open keeps the route it started on); (b) the user runs `claude-glm --resume` in a terminal of that repository and picks the earlier conversation, while this session keeps waiting for the handoff of the same run directory (step 6's `--attach` continues a wait that has timed out).
