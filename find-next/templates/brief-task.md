# 任务：处理 wayfinder task 票 #<票号>（只允许 Brief 写明的范围）

## 目标

仓库 `<仓库路径>`（GitHub `<owner/name>`）的地图 #<地图号>「<地图标题>」里，
task 票 #<票号>「<票标题>」已在前沿。你要先判断它的每一步由谁做：只有需要
用户本人身份或凭据的外部操作（首次登录授权、付款、验证码）、物理动作才必须
由人做；能由 agent 做的，你在允许范围内直接做完，其余写成带护栏的运维步骤
交给实现者。主会话会复核结果，再按 wayfinder 格式写 Resolution、关票、更新地图。

## 先读

- 票和评论：`gh issue view <票号> --repo <owner/name> --comments`
- 地图与已有关联决策：`gh issue view <地图号> --repo <owner/name> --comments`
- 相关材料：<主会话列出的文件 / issue / 服务信息；没有写「无」>
- wayfinder 的 task 票与 Resolution 格式：<wayfinder SKILL.md 路径>

## 允许范围

- 可修改的文件或数据：<明确文件/目录/服务对象；没有写「无，只能写运行目录」>
- 可执行的操作：<明确命令 / 外部操作 / 访问方式；没有写「无」>
- 明确禁止：<主会话补充；没有写「无」>

## 要求

1. 判断 AFK / HITL：只有需要用户本人身份或凭据的外部操作（首次登录授权、付款、验证码）、物理动作算 HITL。「在本机执行」「需要真实环境」都不算——前者是在本机执行的运维步骤，后者是经 ssh-manager 或驱动 Orca 做的运维步骤，都带护栏交给实现者；需要放宽权限也不算（见第 4 条）。不把长任务伪装成人件。
2. AFK 可完成时，只在允许范围内做完；每条结果记录事实、位置和后续决策会用到的信息。
3. 运维步骤：每步写明执行方式（在本机执行 / 经 ssh-manager 执行 / Orca 操作序列）、具体动作、预期证据和护栏（只操作哪些对象、改前怎么备份、怎么回滚）。自己不做超出允许范围的部分，把它留给实现者。
4. 需要放宽权限才能做的步骤：不执行，也不替用户决定放宽，单列为该步的「放宽项」。实现者同样不执行，把它写进结果报告的「未执行的放宽项」，该条验收按「已记录」算过。
5. HITL 必须做时，不尝试绕过；把每一步写成用户可执行的精确动作，包含需要提供的结果。
6. 不把 task 扩展成实现目的地本身，不改规格、执行票或地图边界。

## 输出

- AFK 完成：写 `<运行目录>/resolution.md`，包含 `## Resolution 草稿`、依据（文件/命令输出/issue 评论）、地图索引行草稿。
- 有需要人做的步骤或运维步骤：写 `<运行目录>/human-checklist.md`，固定两节，没有内容的节写「无」、不省略节标题：
  - `## 需要本人做的`：每条包含动作、入口/命令、需要回传的结果、预计影响。
  - `## 运维步骤（带护栏，主会话派实现者执行）`：每步包含执行方式（在本机执行 / 经 ssh-manager 执行 / Orca 操作序列）、具体动作、预期证据、护栏、放宽项（没有写「无」）。运维步骤由主会话派实现者执行：`codex-worker.sh` 不带 `--read-only`、按需 `--mcp ssh-manager`、护栏原文照抄进 Brief，结果写回 task 票的 Resolution；派发规则写在 `find-next/SKILL.md`，这里只点名。
- 最终回复不超过 12 行，说明 AFK/HITL 的分类、完成情况、结果文件路径。wrapper 会把最终回复存成 `result.md`；不要自己写 `result.md`。

## 环境约束（找文件与子进程）

- Brief 里引用的仓库外文件都是确切路径（写 Brief 前已用系统索引或 `ls` 核实存在）。某个路径定位不到时，在输出里明写「未定位到，不作为依据」，不要按模糊路径自行全盘搜索。
- 不对 `$HOME` 或仓库目录之外做无边界 `find`：云盘同步目录（如 macOS 的 `~/Library/CloudStorage`）会被它触发按需拉取，看起来就像卡死。要搜系统用系统索引（macOS 用 `mdfind`；其他平台用系统索引工具或对已知子目录定点查找）；非用 `find` 不可时，剪枝挂载点本身，如 `find "$HOME" -path "$HOME/Library/CloudStorage" -prune -o …`。注意 `-not -path` 只过滤输出、不剪枝，照样会走进挂载。
- 结束前收割自己起的、仍在跑的长子进程（起时记下 pid，结束时 kill），不要留下卡死的孤儿进程。

## 不要做

- 不认领、不评论、不关票、不改标签、不建 issue、不改地图
- 不 push、不开 PR、不合并；除非 Brief 明确允许，不 commit
- 不超出「允许范围」修改文件、调用服务或执行命令
- 不递归删除目录，不绕过仓库或全局代理的网络限制
