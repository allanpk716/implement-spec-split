# 任务：处理 wayfinder task 票 #<票号>（只允许 Brief 写明的范围）

## 目标

仓库 `<仓库路径>`（GitHub `<owner/name>`）的地图 #<地图号>「<地图标题>」里，
task 票 #<票号>「<票标题>」已在前沿。你要先判断它能否由 agent 独自完成：
能完成就直接做完；必须由人做的，产出一份精确清单。主会话会复核结果，
再按 wayfinder 格式写 Resolution、关票、更新地图。

## 先读

- 票和评论：`gh issue view <票号> --repo <owner/name> --comments`
- 地图与已有关联决策：`gh issue view <地图号> --repo <owner/name> --comments`
- 相关材料：<主会话列出的文件 / issue / 服务信息；没有写「无」>
- wayfinder 的 task 票与 Resolution 格式：<wayfinder SKILL.md 路径>

## 允许范围

- 可修改的文件或数据：<明确文件/目录/服务对象；没有写「无，只能写运行目录」>
- 可执行的操作：<明确命令 / 外部操作 / 访问方式；没有写「无」>
- 明确禁止：<主会话补充；没有写「无」>

## 要求

1. 判断 AFK / HITL：只依据操作权限、外部身份、物理动作或安全边界判断，不把长任务伪装成人件。
2. AFK 可完成时，只在允许范围内做完；每条结果记录事实、位置和后续决策会用到的信息。
3. HITL 必须做时，不尝试绕过；把每一步写成用户可执行的精确动作，包含需要提供的结果。
4. 不把 task 扩展成实现目的地本身，不改规格、执行票或地图边界。

## 输出

- AFK 完成：写 `<运行目录>/resolution.md`，包含 `## Resolution 草稿`、依据（文件/命令输出/issue 评论）、地图索引行草稿。
- 需要人做：写 `<运行目录>/human-checklist.md`，每条包含动作、入口/命令、需要回传的结果、预计影响。
- 最终回复不超过 12 行，说明 AFK/HITL、完成情况、结果文件路径。wrapper 会把最终回复存成 `result.md`；不要自己写 `result.md`。

## 不要做

- 不认领、不评论、不关票、不改标签、不建 issue、不改地图
- 不 push、不开 PR、不合并；除非 Brief 明确允许，不 commit
- 不超出「允许范围」修改文件、调用服务或执行命令
- 不递归删除目录，不绕过仓库或全局代理的网络限制
