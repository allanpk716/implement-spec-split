# 任务：为 wayfinder 决策票准备一轮用户决策题（只读）

## 目标

仓库 `<仓库路径>`（GitHub `<owner/name>`）的地图 #<地图号>「<地图标题>」里，
决策票 #<票号>「<票标题>」（类型 `grilling`）已在前沿。
你要读票、地图、相关 ADR 和代码，替主会话准备一条手机友好的决策题。
主会话会把它和其他问题合成一轮问用户；用户答完后再写 Resolution、关票、更新地图。

## 先读

- 票和评论：`gh issue view <票号> --repo <owner/name> --comments`
- 地图与 Decisions so far：`gh issue view <地图号> --repo <owner/name> --comments`
- 相关规格 / 执行票 / ADR / 代码：
  <这里列出主会话已经确认的相关文件或 issue，没有写「无」>
- 需要对齐格式的 wayfinder `SKILL.md`：
  <wayfinder SKILL.md 路径>

## 要求

1. 问题陈述必须是一两句自然语言，能让没读地图的用户明白要拍什么板。
2. 给 2–4 个互斥选项；每个选项一行代价或影响，不写空话。
3. 给一个推荐答案和理由。推荐可以综合已有决策、ADR、代码先例和实施成本。
4. 如果票其实不需要用户拍板（例如答案已被 ADR 定死），明确说「无需用户决策」并给 Resolution 草稿。
5. 不替用户回答 HITL 问题；不把安全、产品语义、范围归属这类决定当作机械细节。

## 输出

写 `<运行目录>/decision.md`，只包含：

```
问题：<一两句>

选项：
A. <选项> — <代价/影响>
B. <选项> — <代价/影响>
C. <可选>

推荐：<A/B/C>。<理由一两句>

Resolution 草稿（按用户答案改写）：
<可直接发布的结论>

地图索引行草稿：
- [<票标题>](<票链接>)：<一行答案>
```

最终回复不超过 12 行：问题、推荐选项、`decision.md` 路径。
wrapper 会把最终回复存成 `result.md`；不要自己写 `result.md`。

## 不要做

- 不认领、不评论、不关票、不改标签、不建票、不写 Resolution、不改地图
- 除 `<运行目录>/decision.md` 外不改动任何文件，不 commit
- 不递归删除目录，不绕过仓库或全局代理的网络限制
