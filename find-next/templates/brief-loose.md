# 任务：分流地图外散票 #<票号>（只读）

## 目标

仓库 `<仓库路径>`（GitHub `<owner/name>`）里，散票 #<票号>「<票标题>」
不属于任何地图或规格。你要读票和相关材料，判断它下一步应该等待时机、
开一张新地图、做一个单独决策，还是作为重复/过时票关闭。主会话会复核建议，
合成到一轮里问用户；用户同意后才由主会话写跟踪器。

## 先读

- 票和评论：`gh issue view <票号> --repo <owner/name> --comments`
- 来源地图（正文 `fromMap` 为 <地图号 / 无>）：
  <有来源地图时写 `gh issue view <地图号> --repo <owner/name> --comments`；没有写「无」>
- 相关规格、执行票、ADR 和代码：
  <这里列出主会话已经确认的相关文件或 issue，没有写「无」>
- wayfinder 的地图格式、Decision ticket 和 Fog of war 规则：
  <wayfinder SKILL.md 路径>

## 要求

1. 只给一个分类：`该开地图`、`单个决策`、`重复或过时` 或 `等待时机`。
2. 每条依据都要指向真实 issue/评论、提交、文件、ADR 或代码位置；不凭标题猜测。
3. 判断等待时机时只陈述条件，不自行认定条件已经满足。
4. 建议开地图时，地图草案必须覆盖原票边界：给标题、Destination、首批 research/决策票、仍说不清的迷雾和阻塞关系；不把无关需求带进来。
5. 建议单个决策时，按决策票格式给问题、2–4 个互斥选项、每个选项的代价、推荐答案和理由；不替用户回答 HITL 问题。
6. 建议关闭时，必须写清被哪张票、哪条 Resolution 或哪次提交覆盖；只说「看起来过时」不够。

## 输出

写 `<运行目录>/triage.md`，只包含：

```
分类：<该开地图 / 单个决策 / 重复或过时 / 等待时机>

依据：
- <issue 评论 / 文件:行 / 提交 / ADR：一句事实>

条件：<等待时机时写还要满足什么；其他分类写「无」>

单个决策：<分类为单个决策时，按问题、选项 A/B/C…、推荐答案填写；否则写「无」>

建议关票：<分类为重复或过时时给一句可发布的依据；否则写「无」>
```

分类为「该开地图」时，另写 `<运行目录>/map-draft.md`，只包含：

```
标题：<地图标题>

## Destination

<一两句可交付边界>

## 首批票

- <票标题>（research/decision）：<一句话问题>
  Blocked by：<#真实票号 / 无>

## Not yet specified

<仍说不清的迷雾；没有写「无」>
```

最终回复不超过 12 行：分类、一句依据、条件（若有）、`triage.md` 路径；
该开地图时另加 `map-draft.md` 路径。wrapper 会把最终回复存成 `result.md`；
不要自己写 `result.md`。

## 不要做

- 不认领、不评论、不关票、不改标签、不建票、不建地图、不接 sub-issue 或阻塞
- 除 `<运行目录>/triage.md` 和（需要时）`<运行目录>/map-draft.md` 外不改动任何文件，不 commit
- 不递归删除目录，不绕过仓库或全局代理的网络限制
