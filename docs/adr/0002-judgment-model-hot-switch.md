# 判断模型可由用户全局热切换到 glm-5.4（不自动降级）

ADR 0001 规定 Opus 不可用时停下、不降级。2026-11-26 Opus 的周额度用到 99%（`orca account list` 的读数），要到周五 10:00 才重置，期间整条管线的结论性判断都没有着落。用户定：由用户拨一个全局开关，把用 Opus 的地方切到 glm-5.4。开关是用户的明确决定，不是系统自己降级。开关分两个角色，一条命令可以同时设：`grill`（Design session 讨论）和 `review`（Opus review 的三类）。分开是因为两类风险不同：讨论有用户在场，好坏当场看得出来，又是长会话；审查多数时候无人值守，意见会被自动采纳并落地。用 Opus 的出口只有两个：`scripts/opus-review.sh`（Opus review）和 `scripts/design-session.sh`（Design session）。两个脚本每次被调用时读 `~/.claude/state/judgment-model`，所以已经在执行的会话在下一次审查时就换模型，不用重启，也不用改会话里的指令。今天只支持 glm-5.4：审查经 `claude-glm` 执行（`--model opus` 在这个启动器里映射到 glm-5.4），Design session 在 Orca 终端里起 `claude-glm`，交接协议不变。

## Considered Options

- **代码审核、草稿审读、失败诊断各给一个角色**：否决。三类走同一个出口，先合成一个 `review`；真要分开时再加，文件按角色记，不用改格式。
- **保持不降级，额度用尽就停车**：否决。周额度要等十几个小时，停车期间管线不产出；用户要的是能自己决定让 glm-5.4 顶上。
- **额度报错（退出码 3）时脚本自动改用 glm-5.4**：否决。无人值守落地会按审查意见自动拍板，审查者悄悄变弱等于让人不知情地合入；要自动兜底也得由用户明确打开，不能是默认行为。
- **在会话内把 `model: opus` 映射到 glm-5.4**：否决。官方订阅会话的模型映射在进程启动时就定了，改不了已经在跑的会话；而且官方会话的编排者本身就是 Opus，额度用尽时整个会话都停了。
- **给 glm-5.4 单独占一个 Orca agent 槽位**：否决。本机 OpenClaude 槽位已经是 flash，改槽位会连带影响规格会话。Design session 改为在 Orca 终端里直接起启动器，不依赖槽位配置。

## Consequences

- 审查者变弱：变成 glm-5.4 审 glm-5.4 写的代码。所以 `opus-review.sh` 在 stderr 报告开关状态，findings 文件首行写明 `判断模型：glm-5.4…`，落地报告和最终报告都要注明。
- ADR 0001 的「不降级」对会话仍然成立：会话不许自己换模型，是脚本按用户的开关执行。退出码 3 照旧按 `quota` 停车。
- 开关按角色各记一个模型和一个到期时间（`--until` / `--for`），到点自动回到 opus；不带就一直生效。一条命令里没提到的角色保持原样。`judgment-model.sh` 不带参数查看两个角色的当前状态。
- Design session 只在启动时读开关：已经开着的交互式会话换不了模型，要接着谈得重开或用 `claude-glm --resume` 续接原对话（见 docs/setup.md 阶段 4）。
- opus 路径逐字不变：没有开关、开关到期或读不出来时，两个脚本的行为和以前一样。
